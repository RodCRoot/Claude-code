# Security review — 2026-10-12

Scope: every `"use server"` module (15 files, plus the inline dev-switch action), all 13 route handlers under `src/app/**/route.ts`, and every page that loads by id from `params`/`searchParams`. Each was checked for authentication, org boundary, athlete/payer scope via `src/lib/authz/policy.ts`, sensitive-note visibility, tampering with hidden fields, and money computed on the server. Also checked: file/export/report downloads, webhooks, public inquiry, login/MFA/invite/reset, dev role switcher, CSV formula injection, XSS, open redirects, SSRF, secrets in logs, and health details leaking through tasks, audits and notifications.

Regression tests: `tests/security.test.ts`. All 11 tests fail on the pre-fix code and pass after the fixes.

## Verified, no change needed

- **Server actions and route handlers.** All of them resolve the viewer on the server and pass it into domain functions that enforce `assertCan`, `requireOnAthlete` and org filters. Hidden ids are re-checked under row locks: bookings, sessions, invoices, memberships, holds, guardianships, threads, form versions, stages, templates and jobs. Comp and override are staff-only. Signing roles are derived on the server from `signingState`.
- **Money.** Checkout amounts come from the invoice balance. Product and POS prices come from `versionOn`. Manual payments are capped at the balance, and refunds at the refundable amount. Return URLs never mark anything paid.
- **Webhooks.** Signatures are verified first: Stripe HMAC with `timingSafeEqual` and a time tolerance, PayPal through the verify API. Unverified bodies are stored only as id/length, and error bodies are generic.
- **Invite and reset tokens.** 256-bit, stored as SHA-256, with expiry. They are single-use (cleared on redeem), and redeeming revokes all sessions.
- **Dev role switcher.** Both the page and its inline action check `APP_MODE=demo && NODE_ENV!=="production"`, and it only signs in users with `is_demo`.
- **XSS.** The only `dangerouslySetInnerHTML` is the QR SVG from `qrcode`. Form Markdown renders through React elements, and `videoUrl` must be `https://`.
- **Open redirects.** None: every redirect target is a fixed path or a server-side id.
- **SSRF.** Server-side `fetch` only reaches fixed provider hosts. The logo URL is stored but never fetched or rendered.
- **Secrets in logs.** Logs are structured (name and message only), and no secrets or payloads are logged.
- **Health details.** Body-map review tasks use generic text. Audit summaries in health modules have no values, and audit logs are owner/admin only. Wellness in progress reports is gated per viewer. Operations has no `health.*` capability, and the kiosk shows only first name, last initial and kiosk alerts.

## Left for a human decision

- **Trusted proxy for client IP.** Inquiry rate limiting and signature evidence (`signAction`) use the first `X-Forwarded-For` hop. The right hop to trust depends on the hosting proxy. Set it once you know the deployment (for example, use `x-real-ip` set by the edge).
- **Coach report scope.** Coaches (`reports.operational`) see org-wide operational reports such as "No-shows" with names of athletes they aren't assigned to (`src/lib/reports.ts:135`). This is attendance data, not health data. Decide whether coach reports should be scoped to their own athletes.
- **Co-parent contact details.** A guardian viewing their athlete's page sees the other guardians' email and phone (`src/lib/people/queries.ts:148`). Confirm this is wanted for separated co-parents (sam/casey).
- **Org-less jobs.** The outbox shows org-less system jobs, such as webhook reprocessing, to every org's admins, and lets them retry or cancel those jobs (`src/lib/messaging/outbox.ts:15`). This is harmless while single-tenant.
- **Rejected-webhook rows.** Unauthenticated callers can grow `webhook_events` with rejected rows. Consider rate limiting at the edge or pruning old rejected rows.
