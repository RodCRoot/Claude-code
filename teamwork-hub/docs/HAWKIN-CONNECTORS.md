# Hawkin Dynamics connectors: evaluation for Teamwork Hub

Purpose: decide how historical and ongoing force-plate data gets from Hawkin Cloud into Teamwork Hub. This is a data-access evaluation only. None of these routes replaces the Hawkin capture app or the plates (see `docs/REPLACEMENT-PLAN.md`, decision 4).

**Evidence level for everything below: publicly documented.** Sources were checked on 2026-10-12 against the public pages listed in each row. Nothing is account-verified: Hawkin account sign-in has NOT been done from this project, and nothing about Teamwork's connectors, licences, data volume, regional instance or organization settings has been inspected (`BLOCKERS.md`). Where a column says "unknown", the public page does not state it.

"Status in the Hub" refers to code in `src/lib/integrations/hawkin/*.ts`, `src/lib/imports/schemas/*`, and tests in `tests/hawkin.test.ts` and `tests/imports.test.ts`.

## Recommended approach

1. **Archived exports plus a small validated import.** With browser access, download Tests and Averages exports with an explicit full date range and "Include Inactive Metrics" on, plus a handful of single-test force-time files. Keep the originals (the Import Center stores them as `import_source` objects with SHA-256). Import one short date range first, resolve identities by hand, read the reconciliation report, and save the confirmed column mapping as a preset. Fix the mapping before importing the rest.
2. **Authorized read-only API backfill with explicit date ranges.** Once an admin-issued refresh token exists (`HAWKIN_REFRESH_TOKEN`, with `HAWKIN_API_BASE` set to the account's instance), run `scripts/hawkin-sync.ts historical <from> <to>` for a short window with auto-commit off, compare the batch with the CSV import of the same window (counts, metric values, timestamps), then extend the windows. The checkpoint only advances when a batch is committed, so a failed or unreviewed window is re-fetched rather than skipped.
3. **Ongoing incremental sync.** After the historical backfill, `incremental` mode uses `syncFrom` from the checkpoint. Review the schema-change warnings on the first runs (new metric fields, missing expected fields, labels absent from `/metrics`). Turn on auto-commit only after identity review has stopped producing questions.
4. **Keep Hawkin capture.** Every route above reads data that Hawkin has already captured. None of them changes decision 4 in `docs/REPLACEMENT-PLAN.md`.
5. **Spreadsheet connectors are optional.** Power Query, the Excel add-in and the Sheets add-on are reporting conveniences. Do not install the add-ins until their write features and credential storage have been reviewed, and never put minors' data in a shared sheet without a reason.

Open verification items before the API route is trusted for completeness: backdated tests versus creation-date windows, retroactive edits under `syncFrom`, the meaning of `timestamp`, the nested `athlete` object shape, the force-time response shape, and rate limits. The Hub keeps every raw payload in `trials.raw_payload`, so a later correction does not need a re-fetch.

## Account inspection checklist (when browser access exists)

Read-only. The goal is to record facts, not to change anything.

- Settings, Integrations: whether an API refresh token already exists, who created it, and when. Do not create a new token; note what would be needed.
- Export controls: which export types are offered, whether a custom date range and "Include Inactive Metrics" are available to this account, and the date format preference in use.
- Available test types and the metric dictionary (`/metrics` equivalent in the UI): list them so the Hub's `knownMetricFields` warnings can be interpreted.
- Regional instance: which host the browser is signed in to (`cloud.`, `eu.cloud.`, `apac.cloud.`), for `HAWKIN_API_BASE`.
- Permissions: the role of the signed-in user and whether an admin role is needed for integrations.
- Connector status: whether Power Query, Excel or Sheets connectors are already enabled or installed for this organization.
- Account restrictions: plan tier, any API or export limits shown, data retention terms, and what the account states about data access after cancellation.
- Data volume: approximate athlete count, test count and date range of the oldest test, to size the backfill.

Never: enable connectors, create broad or long-lived tokens, install add-ins, change organization settings, or send athlete data to any third party. Record findings in `BLOCKERS.md` and update the evidence level of the affected `FEATURE_MATRIX.md` rows from publicly documented to account-verified.

Restating plainly: Hawkin account sign-in has NOT been verified from this project, and nothing about Teamwork's connectors, licences, data volume or organization settings has been inspected. Every statement above is from public documentation or from this repository's code.
