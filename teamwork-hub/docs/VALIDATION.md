# Validation map: risk scenarios to existing tests

This maps each risk scenario from Rod's planning brief to the automated tests that exist today in `tests/` (Vitest against real Postgres) and `e2e/` plus `tests/*.e2e.ts` (Playwright). Test names are quoted from the `it(...)` and `test(...)` calls as of 2026-10-14. "Covered" means the scenario's core claim is exercised by a test; "partial" means part of it is; "NOT covered" means no automated test exercises it. Provider-facing tests (Stripe, PayPal, Hawkin) run against signed or mocked fixtures only; none has been run against a sandbox or a live account (`FEATURE_MATRIX.md`).

## Gaps

Scenarios with no automated coverage of the stated claim:

1. **Protocol disclosure on performance comparisons (scenario 11).** Unit mismatches are refused, but nothing tests that comparing sessions recorded under different test types or protocols is labelled or blocked. A test would create two test types with different `protocol` text for the same metric and assert the athlete trend or group comparison flags them.
2. **Restore and export round trip (scenario 12).** `pnpm restore:check` is a manual script. There is no automated restore in CI and no test that imports a `teamwork-export/1` zip into an empty organization and reconciles record counts against `manifest.json`.
3. **Force-plate capture preservation during cutover (scenario 13).** Not testable in this codebase; it must be a checklist item in `docs/REPLACEMENT-PLAN.md` and confirmed by a person.
4. **Staff MFA enforcement by org policy (scenario 14).** No test exercises `requireStaffMfa`.

Partial items worth closing:

- A browser test that opens an athlete page as a coach and asserts staff-only notes are absent (scenario 2).
- A test for the documented duplicate risk when a Hawkin CSV without a Test ID is imported next to API-synced tests (scenario 8).
- A browser test of the membership "Cut over" step (scenario 13).

Everything marked covered above still carries the global caveat from `FEATURE_MATRIX.md`: provider integrations are tested with fixtures and mocks, never against a sandbox or a live account.
